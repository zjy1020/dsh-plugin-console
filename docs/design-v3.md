## §0 设计立场

**产品、受众、首要任务。** 这是一个本地开发者工具，管理**一台机器**上 DSH 各 profile 的插件：装了哪些、能不能更新、卸掉、从 GitHub 装、翻市场（8281 条目录）。受众是一个人——这台机器的使用者，每天看它两三次，每次 30 秒到 2 分钟。因此界面的首要任务只有一条：**让我在 3 秒内看清「我的插件现在处于什么状态、有哪些能更新、上一次操作到底改了什么」**。它不是营销页，没有 hero；它的「第一屏主体」是数据本身和它的差异。所有氛围性材质只有服务于这个任务时才存在。

**一处记忆点。** 我选的记忆点是**缝隙刻度（gap strip）**——侧边栏状态区里那条 4px 宽、按 `bundles` 下标排列的刻度带。侧栏展开态是横向 18px 高的一条，收起态旋转成 8px 宽的竖向柱（42 段 × 1.5px），两种状态都在。

它属于这个产品，因为本工具的核心语义就是「装了 ≠ 加载了」：一个包可以存在于该 profile 的 `dependencies` 里，却不在 `bundles` 数组里——那就等于装了但从未被运行时装起来。缝隙刻度的每一格是一次真实的存在性判定：在 `bundles` 里的是实心刻度，被移出的是**下沉 3px 的空心缺口**，缺口旁边 hover 出「`@scope/pkg` · bundles 无此下标」。整条带子就是「这个 profile 的静默失效清单」，点击缺口直接跳到「已停用」筛选。它不是装饰，是一条**可以逐位读的机器状态**；其它任何插件管理器都不会长这条东西。全部其余部分（品牌、导航、用户区）保持安静——没有第二个动画主角、没有第二处品牌色的花活。

**我拒绝的两件事（别人会做，我不做）。**

1. **不做「每项各闪一下」的选中反馈。** 常见做法是给当前导航项加发光边框或渐变底再各自过渡。我改成客户要的那一块**玻璃滑块**：选中背景是一个物理实体，在菜单项之间平移（§2.4），菜单项本身只在滑块到达时把文字色与图标从 `--fg-1` 提到 `--fg-0`。理由：一块会移动的玻璃表达的是「选择是一个位置」，而每一格自己闪一下表达的是「点击发生过」——前者对每天用 30 次的工具是更省认知的语法，且它天然避免了「每项都发光」。
2. **不做「面板打开时整体 fade-and-slide-up」的开屏编排。** 唯一的编排留在**壁纸刚切换**和**壁纸自动适配完成**这两处（§2.6），因为那两处是真的「世界变了」。侧栏展开/收起只做宽度与内容交叉淡化，140ms，不位移。理由：这是窗口内每天开关几十次的面板，任何一次位移都会在第二次以后变成噪音；而素材变化时的编排每次都必须重新理解，编排此时有信息量。

**张力：氛围性毛玻璃 vs 高密度技术数据——我怎么解。**

我同意「材质是壳，数据是硬的」，并把它落成三条可执行的硬规则，而不是一句态度：

- **数据永远不落在模糊层上。** 所有数字、版本号、semver 徽章、`bundles` 下标、延迟毫秒、计数，必须先坐在一块**数据衬底**上：`--mt-bed-tint` 深色 alpha 0.72 / 浅色 0.80，外加 1px 描边与 8px 局部 blur，衬底之下才是壁纸。文字颜色一律用**纯色** `--p-mist` / `--p-ink`（不用 alpha 文字色），确保合成对比：正文 ≥ 4.5:1、数字与版本 ≥ 7:1。任何「为了融合而把数字调灰」的取值都算设计缺陷。
- **模糊预算是分配的不是铺开的。** 面板中央（数据区）的 blur 只作用在衬底之外的那一圈；亚克力的「融合感」由**外边缘 24px 的折射环 + 面板外的 10px 留白**提供，而不是把整块区域糊掉。这条同时解决了「壁纸比内容抢眼」——融合发生在外围，内容区始终清晰、低反差、低饱和。
- **壁纸永远比内容弱一档。** 自动适配给出的遮罩 alpha 有一个下限（深色模式不低于 0.28，浅色不低于 0.16），且当判定为「复杂主体图案」时上限提高 0.10。壁纸是地面的纹理，不是海报。

如果非要一句更好的说法：**不是「玻璃上放数据」，是「玻璃柜里放仪器」——柜子是氛围，仪器是硬的，指针的读数从来不由玻璃决定。**

## §1 Token 系统

全部为**在现有 `tokens.css` 上追加**，不推翻：`--bg-*` / `--fg-*` / `--accent*` / 语义色 / `--dur-*` / `--ease-*` 全部保留，它们的值可以按本文档 §4 微调但名字不动（现有 6 个 css 文件、17 个组件都在引用）。新增的玻璃层变量统一前缀 `--mt-`（material）、`--gl-`（glass）、`--wp-`（wallpaper）、`--sb-`（sidebar）。

### 1.1 核心色板（两套，角色一一对应）

**深色（默认）——不是纯黑，蓝紫偏移；不是深蓝，保留黑度。**

| token | hex | 角色 |
|---|---|---|
| `--p-ink` | `#0C0E16` | 玻璃母色。面板基色、遮罩基色、阴影基色。HSL 232°，比现有 `--bg-0 #0a0c11` 略亮、更紫一点点 |
| `--p-slate` | `#171B26` | 抬升与衬底基色。数据衬底、抬起的控件、滑块空槽 |
| `--p-mist` | `#E8ECF4` | 前景主色。文字、数字、图标（perceptual 亮度 L\*=0.90，禁止用纯 `#FFF` 做正文） |
| `--p-brand` | `#4C9AFF` | 品牌冷蓝。**只允许出现在六处**（见下） |
| `--p-aurora` | `#7C6CF0` | 辅助蓝紫。仅用于：主题身份标记、差异视图「新增位」、玻璃滑块内折射 |
| `--p-ember` | `#E0A45C` | 注意色（暖琥珀）。待处理、可更新、缺口刻度、未测延迟 |

**浅色——不是一片纯白；是雾面冷白，面板本身半透明叠壁纸。**

| token | hex | 对应深色 |
|---|---|---|
| `--p-ink` | `#EFF2F7` | ↔ `#0C0E16`（母色：深色的「墨」在浅色里是「雾」） |
| `--p-slate` | `#E2E7F0` | ↔ `#171B26`（衬底/抬升基色） |
| `--p-mist` | `#12151C` | ↔ `#E8ECF4`（前景：近黑带蓝，不用 `#000`） |
| `--p-brand` | `#1F6FEB` | ↔ `#4C9AFF`（同色相，压暗提对比） |
| `--p-aurora` | `#6B5BE0` | ↔ `#7C6CF0` |
| `--p-ember` | `#A96A18` | ↔ `#E0A45C`（浅底上必须压暗才能到 4.5:1） |

**品牌强调色的白名单（只此六处，其余一律不允许）：**
1. 当前选中导航项的文字/图标（滑块到达之后 60ms）；
2. 玻璃滑块内部的折射色，alpha ≤ 0.10；
3. `:focus-visible` 焦点环（2px，offset 1px）；
4. 主操作按钮的实底（`.btn--primary`）与进度条填充；
5. 状态点的「运行中 / 同步中」两态；
6. 链接型操作文本。

**明确禁止**：正文用品牌色、图标默认色用品牌色、全局边框用品牌色、分区标题用品牌色、把品牌色当渐变装饰铺在任何大面上。品牌色是「哪里是当前状态」的语言，不是皮肤油漆。

语义色沿用现有 `--danger / --warn / --ok` 三个名字并微调为与 `--p-ember` 同族：`--danger: #F2645E`（深）/ `#C0392F`（浅）、`--warn: #E0A45C` / `#A96A18`、`--ok: #4FD08E` / `#1A7F4B`。**六态状态点的颜色全部来自这三个 + 品牌色，不新增第五种色相。**

### 1.2 字体

两套，明显区分，且 **Windows 上一定拿得到**（不引入任何 web font、不下载任何字重文件）：

```css
--font-ui: "Segoe UI Variable Text", "Segoe UI Variable Display", "Segoe UI",
           system-ui, "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-num: "Cascadia Mono", Consolas, "Microsoft YaHei UI", monospace;
--font-ui-display: "Segoe UI Variable Display", "Segoe UI Variable Text", "Segoe UI",
           system-ui, "Microsoft YaHei UI", sans-serif;   /* 仅 ≥17px 使用 */
```

- UI 字体：Win11 自带 Segoe UI Variable（可变字重，`wght` 轴可用）；中文落到 `Microsoft YaHei UI`（Win10/11 都自带）。**不使用** Inter / Roboto / Geist 这类需要自带的字体。
- 数字字体：`Cascadia Mono` 随 Windows Terminal 分发，**不能假定存在**，因此第一备选必须是 `Consolas`（Win 全系自带）。所有数字强制 `font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1, "zero" 1;`——零带斜杠，避免 `0`/`O` 混淆。
- **等宽白名单（重要，直接对应黑名单第 5 条）**：等宽只给**机器字符串**——semver 版本、`github:owner/repo` spec、路径、hash、`bundles` 下标、毫秒数、目录条数。**人类数值**（`42 个插件`、`已选 3 项`、`第 2 / 5 步`）用 UI 字体 + `tabular-nums`。现有 `.badge--mono` 目前无差别套用，§6 会改。

**字号阶梯（流式，1440px 窗口下为实测值）：**

| token | `clamp()` | @1440 | 字重 | 字距 | 行高 | 用途 |
|---|---|---|---|---|---|---|
| `--fs-caption` | `clamp(10.5px, 0.60rem + 0.09vw, 11.5px)` | 10.9 | 400 / 500 | +0.01em | 1.35 | 刻度 tooltip、kbd、角标数字 |
| `--fs-meta` | `clamp(11.5px, 0.68rem + 0.09vw, 12.5px)` | 12.2 | 400 | +0.01em | 1.45 | 副行、hint、路径、次要状态 |
| `--fs-body` | `clamp(12.5px, 0.74rem + 0.10vw, 13.5px)` | 13.3 | 400 / 500 | −0.006em | 1.55 | 正文、导航标签、列表主行 |
| `--fs-num` | `clamp(13px, 0.78rem + 0.10vw, 14.5px)` | 13.9 | 600 | 0 | 1.15 | 行内数字读数（计数、版本并排） |
| `--fs-title` | `clamp(14px, 0.82rem + 0.16vw, 16px)` | 15.4 | 600 | −0.008em | 1.30 | 面板标题、软件名、卡片标题 |
| `--fs-readout` | `clamp(17px, 1.00rem + 0.28vw, 21px)` | 20.0 | 600 | −0.01em | 1.05 | **唯一的重量级读数**：代理延迟 `38 ms`、diff 位数 |
| `--fs-display` | `clamp(20px, 1.24rem + 0.36vw, 26px)` | 24.1 | 600 | −0.012em | 1.15 | 设置中心页标题（一屏最多一处） |

- **行长上限**：正文区 `max-inline-size: 72ch`；设置面板的说明文本 `62ch`；错误详情 `76ch` 且允许换行。版本号/路径一永不换行，`truncate` + `title` 全文。
- **字距纪律**：只有 `--fs-caption` 允许正的 `+0.01em`（小字需要一点点呼吸）。**禁止任何 ≥0.06em 的字距**——现有 `.section-title` 的 `0.06em` + `text-transform: uppercase` 在 §6 被替换为「中文分组名 + 0.02em」。

### 1.3 间距、圆角、层级

**间距刻度**（4px 基，前段密后段疏，符合桌面工具的真实需要）：

```css
--sp-hair: 2px;  --sp-1: 4px;  --sp-2: 8px;  --sp-2h: 10px; --sp-3: 12px;
--sp-3h: 14px;   --sp-4: 16px; --sp-5: 20px; --sp-6: 24px;  --sp-8: 32px;
--sp-10: 40px;   --sp-12: 48px;
```

**侧栏专用节奏**（把「区与区之间的留白必须不同」写成数值，避免节奏均匀的 SaaS 感）：

```css
--sb-margin: 10px;        /* 悬浮面板到窗口边缘 */
--sb-w-expanded: 264px;
--sb-w-collapsed: 64px;
--sb-pad-x: 12px;         /* 展开；收起为 10px（44px 内容区） */
--sb-item-h: 34px;        /* 展开态导航项 */
--sb-item-h-collapsed: 40px;  /* 收起态：图标要更大更居中，这是重设计不是隐藏文字 */
--sb-icon: 16px;          /* 展开 */ --sb-icon-collapsed: 18px;
--sb-gap-brand-quick: 8px;
--sb-gap-quick-nav: 16px;
--sb-gap-nav-status: 16px;
--sb-gap-status-user: 24px;   /* 客户要求：用户区与主导航之间有明显留白 */
--sb-group-head-h: 22px;
--sb-group-gap: 10px;
```

**圆角刻度（禁止全站一个值）：半径随元素高度递减，`r ≈ min(h × 0.28, 22px)`。**

| token | 值 | 用在哪 | 为什么是这个值 |
|---|---|---|---|
| `--r-hair` | 1px | 刻度带 tick、进度条、分隔线端头 | 1px 的细节上圆角=像素模糊，只保留端头软化 |
| `--r-xs` | 3px | 17px 高的徽章、kbd、角标 | 小元素在大圆角下会变「药丸」，失去数据感 |
| `--r-sm` | 6px | 28–34px 的按钮、输入框、导航项、状态点外框 | 34×0.28≈9.5，但导航项要锐，取 6 |
| `--r-md` | 10px | 状态卡、主题卡、滑块槽、缩略图 | 84px 高卡片 ×0.28≈23 太大，取 10 保底 |
| `--r-lg` | 16px | 悬浮侧栏面板、弹窗、设置面板 | 面板高 ≥600，圆角是它的签名，允许大 |
| `--r-xl` | 22px | 壁纸预览大卡、拖拽遮罩内框 | 上限值 |
| `--r-full` | 999px | 头像、状态点、开关轨道、logo 容器 | 纯圆形语义 |

**z-index 刻度**（现有只到 80，新增需要 6 档）：

```css
--z-wallpaper: 0;      /* 壁纸层 ::before */
--z-content: 5;        /* 主区内容 */
--z-shell: 10;         /* 侧栏悬浮面板 */
--z-slider:    11;     /* 玻璃滑块：在导航项之下（12），但高于面板底 */
--z-item:      12;     /* 导航项图标与文字（滑块之上） */
--z-panel-edge:14;     /* 面板外缘折射环 */
--z-sticky:    20;
--z-scrollbar: 30;
--z-drag:      50;     /* 拖拽遮罩 */
--z-popover:   60;
--z-drawer:    70;
--z-dialog:    90;
--z-toast:    100;
```

关键关系：**滑块（11）必须低于内容（12）**——玻璃在文字下面；**面板外缘折射环（14）高于内容**，因为它只画在面板边缘 24px 内，不覆盖任何文字。

**目录条数的 z 无关但有关**：8281 条市场目录的虚拟列表滚动条用 `--z-scrollbar: 30`，高于 sticky 头，因为它需要一直可抓。

### 1.5 材质 token（四层，深/浅各一份）

四层必须**透明度各不相同**（客户硬要求），且每层职责单一：

- **L0 背景层**：壁纸 + 全局遮罩（`--gl-veil-*`）。承载图像本身，不做 blur。
- **L1 内容层**：亚克力面板本体（`--gl-panel-*`）+ 数据衬底（`--gl-bed-*`）。
- **L2 高光层**：只三处、只有事件、320ms 衰减到 0（`--gl-hl-*`）。
- **L3 阴影层**：面板与浮层的投影（`--gl-sh-*`）。

四层 alpha 汇总（证明它们真的不同）：**L0 0.34 / L1 0.52 / L1' 0.72 / L2 峰值 0.14 / L3 0.62**（浅色：0.16 / 0.46 / 0.80 / 0.30 / 0.28）。

**「假玻璃」预合成分支**（低性能设备与「同时打开的浮层 > 2」时切换）：把壁纸先按裁剪区域降采样 64px、高斯模糊 12px、按 `--gl-panel-alpha` 混色成一张静态数据 URI 作为面板底，代价是滚动时与壁纸不同步——因此只在 `prefers-reduced-transparency: reduce`、或 GPU 评分低于阈值、或浮层数 > 2 时启用。

**高光纪律（写成硬约束）**：
- `--gl-hl-*` 只允许在六个事件上出现：`hover-in`、`选中变化`、`面板刚打开`、`壁纸刚切换`、`主题变化`、`操作成功`。全部为一次性 transition，**不允许任何 `animation-iteration-count: infinite` 的高光/扫光/沿边框移动**。
- 高光实现方式统一为「叠加一层 `--gl-hl-sheen` 的伪元素，opacity 0 → 1 → 0」，用 `@property` 或双帧 transition 保证可中断。

### 1.6 高层原则（指导取舍，不是口号）

1. **数字是硬的。** 任何数字/版本/徽章必须有 ≥0.72 alpha 的数据衬底，合成对比：正文 ≥4.5:1、数字与版本 ≥7:1。取值冲突时，牺牲融合，保留读数。
2. **高光是事件，不是状态。** 寿命 320ms、峰值 0.14、必须衰减到 0。任何「一直亮着」或「一直沿边框走」的高光按 bug 处理。六个允许事件之外不得出现高光。
3. **半径随高度递减**（`r ≈ min(h×0.28, 22px)`）。大面板可以柔，徽章必须锐；全站统一一个圆角值即视为设计失败。
4. **一屏只有一个主角。** 会「明显动」的只有玻璃滑块；其余动效一律 90–240ms 的位移或透明度，不做弹跳、不做位移入场。
5. **壁纸永远弱于内容**：遮罩 alpha 有下限（深 ≥0.28 / 浅 ≥0.16），判定为复杂主体图案时再 +0.10；任何情况下数字区不被 blur 覆盖。
6. **键盘与高对比是硬地板**：每个可点元素有 `:focus-visible` 2px 品牌环；`forced-colors: active` 下面板全部退化为纯色 + 系统边框（§3.16），此时玻璃与外缘折射环整体关闭。

## §2 动效 token

### 2.1 时长与缓动

```css
--t-1:  90ms;    /* 按压、颜色微变、hover 文字色 */
--t-2: 140ms;    /* 图标/文字交叉淡化、面板展开收起、tooltip 进出 */
--t-3: 200ms;    /* 玻璃滑块位移基线、状态卡数值滚动 */
--t-4: 320ms;    /* 高光衰减、主题切换、反馈脉冲 */
--t-5: 520ms;    /* 壁纸切换编排、自动适配三段式 */
--t-6: 900ms;    /* 壁纸淡入（唯一长时动效） */

--e-standard: cubic-bezier(0.20, 0.00, 0.00, 1.00);  /* 默认：Fluent 标准曲线 */
--e-decel:    cubic-bezier(0.10, 0.90, 0.20, 1.00);  /* 进入视口/展开 */
--e-accel:    cubic-bezier(0.70, 0.00, 1.00, 0.50);  /* 离开/收起 */
--e-glass:    cubic-bezier(0.32, 0.72, 0.00, 1.00);  /* 玻璃滑块专用：无过冲的长尾 */
--e-linear:   linear;
```

### 2.2 spring：只允许三处

```css
--spring-slider:  stiffness 420, damping 42, mass 0.9;  /* 〔待 ref-notes 校准〕 */
--spring-pulse:   stiffness 600, damping 18, mass 0.7;  /* 〔待 ref-notes 校准〕 */
--spring-drop:    stiffness 380, damping 30, mass 1.0;  /* 〔待 ref-notes 校准〕 */
```

1. **玻璃滑块的位置**（`--spring-slider`）：420/42 在临界阻尼附近，视觉上是一次「稳稳停下」的位移，快速连点两次导航时会有 0.5–1px 的 settle——那一点点才是「玻璃」的手感。超过这个量就是弹跳玩具，禁止。
2. **状态点「成功」脉冲**（`--spring-pulse`）：一次 1 → 1.18 → 1 的缩放，只播一次。
3. **拖拽遮罩释放**（`--spring-drop`）：松手后遮罩外框回落 6px 并淡出。

**明确不用 spring 的**：

- **跟随类**（光标跟随、滚动同步、进度跟随、拖动中的滑块）**不是 spring 问题**，是一阶低通：`x += (target − x) · min(1, dt · k)`，滑块跟随 `k = 18 /s`、滚动条 `k = 26 /s`、拖拽中的预览轮廓 `k = 40 /s`（要跟手）。稳态滞后 `Δ = v / k`，例如 600px/s 的快速拖动、k=18 时滞后 33px——**这个数字本身就是选 18 的理由**：能看出「落后一点」但不超过一个菜单项的宽度。
- **面板滑入/展开**不用 spring，用 `--t-2 + --e-decel`（进入）/ `--e-accel`（收起）。面板是空间的边界，不是玩具。
- **列表项 stagger**：取消。不做「每项依次淡入」。

### 2.3 状态点六态动效

| 状态 | 视觉 | 动效 | 时长 |
|---|---|---|---|
| 在线 | 实心 `--ok` 6px + 外环 0.18 alpha | 无动效（静止即「一切正常」） | — |
| 运行中 | 实心 `--p-brand` 6px + 外环 0.22 | 外环 8px→14px 呼吸，opacity 0.22→0，2.4s 一次 | 2400ms ∞（唯一允许的无限动效，且是「状态」不是「装饰」） |
| 加载中 | 环状缺口 6px | 旋转 900ms linear ∞ | 900ms |
| 成功 | 实心 `--ok` → 短暂 18px 外扩环 | `--spring-pulse` 单次 + 环 320ms 淡出 | 320ms |
| 失败 | 实心 `--danger` + 1px 描边 | 一次 ±0.6px 横向抖动 ×2 | 2×70ms |
| 离线 | 空心环 1px `--fg-2` | 无动效 | — |

「运行中」的呼吸是六态里唯一无限循环的动效，因为它**表示持续状态**；其余全部为一次性。`prefers-reduced-motion` 下「运行中」退化为静态实心 + 常驻外环。

### 2.4 玻璃滑块（选中移动）

- 唯一载体：一个绝对定位的 `div.gl-slider`，`transform: translateY()`（竖向侧栏）平移，尺寸随目标项高度过渡（`--sb-item-h` 34 / 收起 40）。
- 时长：`--t-3` + `--e-glass`；快速连点（间隔 <120ms）时改走 `--spring-slider`，这样连续切换像被甩过去的实体，而不是排队执行的动画。
- 内容：`background: linear-gradient(100deg, var(--p-brand-08), transparent 62%)` + 1px 内描边 `--gl-panel-edge` + 面板底 `--gl-bed-alpha: 0.7` 的实色（保证选中项文字也可读）。
- 到达后 60ms，目标项文字/图标从 `--fg-1` 提到 `--fg-0`，源项反向（`--t-2`）。
- **禁止**：滑块带扫光、带拖尾、带阴影跟随；滑块本身不再叠高光层（它已经是高光事件的结果）。

### 2.5 五类事件的编排

| 事件 | 编排（严格串行） |
|---|---|
| **打开**（侧栏首次出现 / 窗口恢复） | 面板 scale 0.985→1 + opacity 0→1（`--t-2 --e-decel`）；60ms 后品牌 logo 内圈高光一次（320ms 衰减）；不做 stagger。总时长 ≤ 400ms |
| **收起** | 宽度 264→64（`--t-2 --e-accel`），文字 opacity 1→0（`--t-1`，先于宽度结束）；图标列不位移（见 §1.4 对齐规则）；结束时不闪 |
| **选择** | 滑块位移（§2.4）→ 60ms → 文字色提升 → 90ms → 右侧数字角标一次 1.06 缩放 |
| **反馈** | 成功：目标元素高光一次 + 状态点脉冲；失败：抖动 ×2 + Toast；进行中：进度条确定值 + `--fs-num` 数字滚动（200ms） |
| **壁纸变化** | 旧壁纸 opacity 1→0 / 新壁纸 0→1（`--t-6`，交叉淡化，**不闪白：始终有一张不透明的图在下层**）；面板材质参数插值（`--t-5`）；高光一次（`--t-4`）；图标 `rotate(-4deg)+scale(0.94)`→复位（`--t-4`，仅这一处图标带旋转） |

### 2.6 两档降级

**A) 系统档 `@media (prefers-reduced-motion: reduce)`**
关掉：壁纸交叉淡化（改瞬时切换）、滑块 spring（改 0ms 直接跳位 + 在新位置画 1px 品牌描边 200ms 后淡出，用于标示「变了」）、状态点脉冲与运行中呼吸、拖拽遮罩光晕、图标旋转/缩放、面板打开编排、数字滚动。
保留：颜色/透明度过渡（压缩到 80ms，避免硬闪）、`:focus-visible` 焦点环、进度条（改为**数字文本** `3 / 8` 而非动画条）、Toast 进出（改为瞬时出现 + 320ms 淡出）。

**B) 应用内档「简化动效」**（设置中心 → 动效，用户手动开，粒度比系统档更细）
关掉**装饰性动效**：高光扫过、图标旋转、状态点呼吸、壁纸切换的视差与编排、滑块 spring。
保留**说明状态变化的动效**：滑块平移（改 150ms `--e-standard`）、展开/收起（180ms）、Toast 进出、数值滚动（240ms）、进度条动画。
即：系统档负责无障碍，应用内档负责「这破机器核显带不动」。两档叠加时取更严的一档。

### 2.7 性能预算（写进验收）

- 任何一次交互的连续动画元素 ≤ 3；同屏 `backdrop-filter` 元素 ≤ 2（超出走假玻璃）。
- 1440×900 下侧栏展开/收起保持 ≥ 55fps（Chrome DevTools 帧耗时 p95 < 18ms）；壁纸交叉淡化期间允许降到 45fps。
- 自动适配计算放进 Worker，主线程单帧阻塞 ≤ 4ms；全流程目标 < 40ms（§5.9）。
- `content-visibility: auto` 用在设置中心五个分区上，市场虚拟列表另行处理（8281 条）。

### 3.22 交互契约（三张清单，供实现时逐条勾）

**设置中心五块（客户点名）——每块只放属于它的东西：**

1. **外观**：深浅模式（跟随系统/深/浅）、品牌色（色板 + 从壁纸取色开关）、辅助色、半透明与模糊的「总开关」（一键关闭所有玻璃 → 降级为实色，为老机器与 `prefers-reduced-transparency`）。
2. **壁纸**：导入（点击/拖拽/最近使用/预设/动态/主题包）、缩略图网格、10 个可调参数（§4.2 表）、**自动适配**按钮、位置建议、恢复默认。
3. **侧边栏**：宽度（220–320，步进 4）、展开/收起默认状态、菜单布局（分组/紧凑两档）、刻度带显隐、收起态显示内容勾选（状态点 / 延迟数字 / 刻度柱）、用户区显示。
4. **动效**：动效等级（完整/简化/关闭）、高光开关、状态点呼吸开关、壁纸切换编排开关，并在此处**明示系统偏好已被检测到**（`prefers-reduced-motion: reduce` 时显示一行「系统已要求减少动效」）。
5. **主题管理**：列表 + 八个操作（保存当前为… / 重命名 / 复制 / 导出 JSON / 导入 JSON / 删除 / 设为默认 / 设为深色基准、设为浅色基准）。

**主题 = 一整套环境**，字段（与 §4 表一一对应，可导出为 JSON）：
`{ name, wallpaper:{type,path,scale,position,brightness,saturation,contrast,blur}, mode, brand, accent, sidebarOpacity, blur, bedAlpha, mask, edgeLuma, shadowStrength, motionLevel, sidebarWidth, menuLayout, defaultExpanded, wallpaperPosition }`
共 **17 个字段**——比客户列的 13 项多出 `bedAlpha`（数据衬底，§0 张力解法必需）、`mask`（深浅遮罩）、`wallpaperPosition`（同一张壁纸在不同主题下裁切不同）。

**键盘可用性（不许为高级感牺牲）：**
`Ctrl+K` 搜索 · `Ctrl+Shift+R` 刷新 · `Ctrl+B` 展开/收起侧栏 · `Ctrl+1..9` 直选前 9 个导航项 · `Tab` 顺序 = 品牌 → 快捷 → 导航 → 状态卡 → 用户区（**收起态与展开态顺序一致**，不让收起态变成键盘黑洞）· `Esc` 逐层关闭 · 设置中心内 `←/→` 切分区 · 滑块 `←/→` 步进 1%、`Shift` 10% · 拖拽导入有等价的「从文件导入」（**拖拽永远不是唯一入口**）。

**高对比模式（`forced-colors: active`）**：玻璃全关（面板 → `Canvas` 底 + `CanvasText` 字 + `1px Solid` 边框）、外缘折射环关闭、状态点带 `border: 1px solid`、刻度带缺口用 `outline` 而非「下沉 3px」（下沉在强制色下不可见）、幻灯片式高光全关。**验收：在 Windows 高对比黑主题下，刻度带的「在/不在」必须仍然可分。**

**「极简灰阶」的品牌色特例（重要）**：当品牌色本身是灰（chroma < 0.03），它就**不能承担「哪里是当前状态」的语义**。因此灰阶主题启用一条降级规则：`--p-brand` 退化为 `--p-mist`，选中状态完全靠**位置与形状**表达——玻璃滑块（位置）、1px 内描边（形状）、文字 400→600（重量）、左侧 2px 指示条（位置）。这条规则同时说明了一件事：**品牌色从来不是「必要的」，位置才是。** 其余四套主题即便把品牌色换成灰也能正常工作（只是少一层提示），这是本设计系统的一个压力测试。

### 4.4 壁纸十个可调参数（范围 / 默认 / 影响面）

设置中心「壁纸」分区，顺序即此表顺序：

| # | 参数 | 范围 | 步进 | 默认 | 影响面 / 备注 |
|---|---|---|---|---|---|
| 1 | 亮度 | 60–140% | 1 | 100% | 只作用壁纸层；>120% 时自动把遮罩 +0.06 |
| 2 | 饱和度 | 0–180% | 1 | 100% | >150% 时建议降低品牌色饱和（提示，不强制） |
| 3 | 对比度 | 70–140% | 1 | 100% | 与「文字安全区」联动：>120% 会扩大衬底范围 |
| 4 | 模糊 | 0–40px | 1 | 8px | **独立于面板 blur**（壁纸自己先糊）；>24px 时触发性能提示 |
| 5 | 缩放方式 | 填充 / 适应 / 拉伸 / 平铺 / 居中 | — | 填充 | 平铺仅在纯色/纹理壁纸下有意义，会自动提示 |
| 6 | 位置 | 9 宫格 + 手动 XY 偏移（−200~200px） | 1px | 居中 | 自动适配输出的 `suggestSidebarSide` 会影响默认值 |
| 7 | 深色遮罩 | 0–0.60 | 0.01 | 主题值 | **有下限**：深色模式 ≥0.28（低于此值数字区对比受威胁时直接拒绝并提示） |

## §5 壁纸自动适配算法

目标：一张壁纸进来，输出 §3.22 那 17 个字段里与材质有关的全部参数，并给出侧栏位置建议与「文字安全区」图。全流程在 Worker 里跑，主线程阻塞 ≤ 4ms，总目标 < 40ms（1440×900 基准机）。

### 5.1 输入与预处理

```ts
type AdaptInput = {
  bitmap: ImageBitmap;      // 原始壁纸（不缩放保存，用后即 close）
  targetSide: 'left'|'right';
  panelRect: { x:number; y:number; w:number; h:number };  // 当前/候选面板占位（CSS px）
  viewport: { w:number; h:number; dpr:number };
  current: ThemeMaterial;   // 当前主题，用于「中间带不切换」的防抖
};
```

预处理三步（只做一次）：
1. **降采样到 256×256**（`OffscreenCanvas` + `imageSmoothingQuality:'high'`，强制 1:1 方形化：按 `object-fit: cover` 的裁切规则先裁再缩，保证分析的就是实际显示的那一块）。
2. 再生成 **64×64**（用于主色聚类与连通性）与 **16×16**（用于全局明暗与位置建议）。
3. 转成两个平面：`Y`（感知亮度，`Y = 0.2126R' + 0.7152G' + 0.0722B'`，其中 `R' = linear(r/255)`，即 **linear 空间算亮度**，避免 sRGB 下算出的「中灰偏亮」）与 `OKLab` 的 `L/C/H`（用于主色与 chroma 判定）。全部转 `Float32Array`，256²×3 ≈ 197k float，可以接受。

**侧栏局部区**：把面板矩形的归一化范围映射到 256×256 上，得到 `zone`（左：`x∈[0, 0.34]`；右：`x∈[0.66, 1]`；若面板宽度 / 视口宽 > 0.34，则按实际宽度取）。

### 5.2 第 1 步 · 明暗判定（不是全图分位数，是「侧栏所在处」的亮度）

```
Lall   = Y 全图按面积加权的均值
Lp50   = Y 的全图 50% 分位数
Lzone  = Y 在 zone 内的按面积加权均值          // 主判据
Lzone_p15 / Lzone_p85 = zone 内的分位数         // 稳定度判据
stability = (Lzone_p85 - Lzone_p15)             // 局部反差
```
判定（阈值写死，可被主题覆盖但要落在带内）：
```
if  Lzone < 0.42                    -> dark
else if Lzone > 0.58                -> light
else                                -> keep current   // 中间带（0.42~0.58）不切换，防抖
最终模式 = 若 current 已在中间带决定的结果上，则不动（迟滞带宽 0.08）
```
**为什么用 zone 而不是全图**：壁纸全图很暗但左上一块阳光（或反过来）时，决定文字可读性的是**面板所在的那块像素**。全图 `Lp50` 只作为兜底（当 zone 面积 < 全图 8% 时使用）并以 0.3 权重融入：`L = 0.7·Lzone + 0.3·Lp50`。

### 5.3 第 2 步 · 主色提取（Android 动态取色思路）

不用 median-cut、不用 `quantize()`（两者都会偏向面积大的背景色）。用 **k-means，k=5，在 OKLab 空间**（OKLab 的欧氏距离近似感知均匀，比 Lab 更省算力也更符合「看起来像不像」）。

```
采样：64×64 = 4096 点，先在 3D 空间做弓形采样（每维 8 档 → 512 个桶），桶内取均值与权重，
      以权重降序取 ≤ 1024 个点作为 k-means 输入（避免大面积纯色主导）。
迭代：k-means++ 初始化，5 次迭代或中心位移 < 1e-3 停止，5 次即可稳定。
产出：clusters[] = { L, C, H, weight }，按 weight·saturation(C) 排序。
```

**Android（Material You / Monet）启发**：Android 的取色不是「拿最大的色团」，而是取种子色后**生成一整条 tonal palette**，并要求生成的强调色与底有足够对比、且避免落在低对比的危险区。这里照搬两条思想：

1. **种子选择**：`seed = clusters` 中 `weight ≥ 0.12 且 C ≥ 0.06` 里 `weight × C` 最大的那个（不是纯粹最大的）。全都不满足 → 判为「无主色」。
2. **品牌色生成（关键约束）**：
```
若 无主色（所有 cluster 的 C < 0.03 或 seed.C < 0.06）:
    brand = 主题预设品牌色        // 灰阶壁纸别硬造颜色（§4.3 极简灰阶就是这条）
否则:
    Δh = +30° 或 −30°，取与「主题预设品牌色」色相更近的那个符号
    brand = OKLCh(0.62, clamp(seed.C × 0.90, 0.10, 0.22), seed.H + Δh)   // 转回 sRGB
    若 brand 对 --p-ink 的对比 < 3.0:1 → L 提到 0.68；仍不足 → L 提 0.72
    // 为什么必须偏移 ±30°：与壁纸同色的品牌色会「消失在壁纸里」，
    // 而偏移过大会让玻璃与壁纸脱节。30° 是「看得出是同一片光、但不是一个颜色」。
```
3. **辅助色** = `OKLCh(0.58, brand.C×0.75, brand.H − 55°)`，用于主题身份与差异视图「新增位」。**永不用辅助色做状态色**（状态色固定为 ok/warn/danger 三族）。

### 5.4 第 3 步 · 「复杂人物图案」判定（低成本、不上人脸模型）

三个信号，加权合成 `busy ∈ [0,1]`：

| 信号 | 算法 | 成本 | 直觉 |
|---|---|---|---|
| `edge` 边缘密度 | 256² 上 Sobel，幅值 `|∇|`；`thr = p95(|∇|)`；`edge = count(|∇| > thr) / N`；再归一化 `edgeN = clamp((edge − 0.01) / 0.20, 0, 1)` | ~2ms | 插画/人像的轮廓多，风景/渐变几乎没有轮廓 |
| `hf` 高频能量比 | `hf = Σ(I − blur₄(I))² / ΣI²`（4px 盒式模糊一遍，可用积分图 O(N)）；`hfN = clamp(hf / 0.06, 0, 1)` | ~1.5ms | 纹理、噪点、毛发；区分「大片平色」与「细节密集」 |
| `skinBlob` 皮肤团块 | YCbCr 判据 `Cb∈[77,127] ∧ Cr∈[133,173] ∧ Y∈[0.20,0.90]`，得比例 `skin`；再在 8×8 网格上做 4-连通，取**最大连通块格数** `blob`；`skinBlob = clamp(skin/0.12,0,1) × clamp((blob−5)/12,0,1)` | ~1.5ms | 人像的皮肤总是**成团**且比例可观；单纯暖色照片不会有皮肤色相 |

```
busy = 0.50·edgeN + 0.30·hfN + 0.20·skinBlob
判为「复杂主体图案」: busy ≥ 0.62
```
**不上人脸检测的理由**：现成的人脸模型（哪怕轻量的）是这个工具里体积与算力最不合理的一块依赖（几十 MB 权重、几十毫秒），而我们真正要回答的不是「是不是人」，而是「侧栏压上去会不会遮住主体、背景会不会干扰文字」——皮肤色团块 + 边缘密度已经回答了后者；前者交给第 5 步的「主体重心」判断（16×16 上求 `edge` 的能量重心 + 皮肤团块重心，两者加权即近似主体位置）。**够用即可，这是桌面工具不是修图软件。**

`busy` 的输出作用：`遮罩 += 0.10×busy`（深色上限 0.46 / 浅色 0.24）、`面板 opacity += 0.06×busy`、`blur += 8px×busy`、`衬底 alpha = max(主题值, 0.72 + 0.08×busy)`、`壁纸亮度 −8%×busy`。

### 5.5 第 4 步 · 文字安全区（逐块算衬底强度）

把面板占位矩形切成 **4×4 = 16 块**（面板内边距对齐网格，块尺寸 = 面板宽/4 × 面板高/4）：

```
对每个块 b:
  · 局部复杂度  c_b = 该块在 256² 上的 edge 密度（同上 Sobel，取均值）
  · 局部背景亮度 Lb_b = 该块的 Y 均值
  · 参考文字色 Lt = (mode==='dark' ? Y(#E8ECF4) : Y(#12151C))
  · WCAG 对比    Cr_b = (max(Lt,Lb_b)+0.05) / (min(Lt,Lb_b)+0.05)
  · 需要的衬底强度 bed_b = clamp( (4.5/max(Cr_b,0.5) − 1) , 0, 1 )   // 对比不足越多，衬底越厚
      c_b > 0.18 时: bed_b = max(bed_b, 0.62)                        // 复杂纹理强制衬底
```
输出是一张 4×4 的 `bed` 强度图。**不要把它渲染成 16 个方块**——用双线性插值升采样成一张 96×96 的单通道遮罩，作为 CSS `mask-image`（或一个 1 通道 PNG 数据 URI）贴在衬底层上。于是衬底不是一块矩形，而是**跟着壁纸局部强弱变化的一层渐变**：在平坦的暗部几乎不存在，在人像的高频区变厚。这是本设计里「氛围与数据共存」最具体的一处实现。

同时输出三个派生值：
- `bedAlpha = max(bed_b over 面板) × 0.92`（全局兜底衬底）
- `textSide = mean(bed) 最小的两列`（文字往哪边靠）——用于长文本左对齐还是给右侧留白
- `contrastReport[]`：逐元素（导航标签 / 读数 / 版本徽章）的前景-背景对比实测值，供 §3.19 预览面板显示与违规框选

### 5.6 第 5 步 · 位置建议

三个候选带（左 0–34% / 中 33–67% / 右 66–100%），每带算一个代价：

```
cost(side) = 0.45·macroComplexity(side)      // 该带 16×16 下的边缘能量
           + 0.35·(1 − flatness(side))       // 亮度方差越大越不适合
           + 0.20·subjectOverlap(side)       // 主体重心（edge 能量重心 + 皮肤团块重心）落在该带的权重
建议侧 = argmin cost；若 |cost(左) − cost(右)| < 0.04 → 保持当前侧（防抖）
```
若主体的重心落在建议侧（例如人像在左而左侧是建议侧）→ 输出 `conflict: true`，并在预览面板提示一行：「主体在左侧，建议侧栏改到右侧，或把壁纸位置右移 18%」，同时给出可直接点的两个动作按钮。**不自动搬家**——位置变化是有体感的破坏性动作，必须由人确认。

### 5.7 第 6 步 · 组装输出

```ts
type AdaptOutput = {
  mode: 'dark' | 'light';                 // 5.2
  brand: string; accent: string;          // 5.3（hex）
  seedHex: string;                        // 来自壁纸的主色，用于色板上的「来源」标记
  sidebarOpacity: number;                 // 主题值 + 0.06×busy，夹到 [0.30, 0.85]
  blur: number;                           // 主题值 + 8×busy，夹到 [12, 40]
  bedAlpha: number;                       // 0.72 + 0.08×busy（深）/ 0.80 + 0.06×busy（浅）
  bedMask: Uint8Array;                    // 96×96 单通道，5.5
  veilDark: number; veilLight: number;    // 主题值 + 0.10×busy，夹到硬下限之上
  edgeLuma: number;                       // 0.10 + 0.02×busy（深）/ 0.70 + 0.06×busy（浅）
  shadowStrength: number;                 // 1.00 + 0.15×busy
  wallpaperBrightness: number;            // 1.00 − 0.08×busy
  suggestedSide: 'left' | 'right';
  conflict: boolean;
  contrastReport: Array<{ el: string; ratio: number; need: number; ok: boolean }>;
  cost: number;                           // 触发时序动画用不到，但记录进主题 JSON 便于复现
};
```

### 5.8 伪代码（可直接实现）

```ts
// worker: wallpaper-adapt.worker.ts
async function adaptWallpaper(input: AdaptInput): Promise<AdaptOutput> {
  // ---------- 0. 预处理 ----------
  const img256 = await resizeCover(input.bitmap, 256, 256);
  const img64  = await resizeFrom(img256, 64, 64);
  const img16  = await resizeFrom(img256, 16, 16);
  const Y256 = linearLuma(img256);                    // Float32Array(65536)
  const ok256 = toOKLab(img256);                      // Float32Array(65536*3)
  const zone = panelZoneToImage(input.panelRect, input.viewport, 256);

  // ---------- 1. 明暗 ----------
  const Lzone = areaMean(Y256, zone);
  const Lp50  = quantile(Y256, 0.50);
  const L     = 0.7 * Lzone + 0.3 * Lp50;
  const mode  = L < 0.42 ? 'dark' : L > 0.58 ? 'light'
             : (Math.abs(L - lumaOf(input.current)) < 0.08 ? modeOf(input.current)
                : (Lzone < 0.5 ? 'dark' : 'light'));   // 迟滞带

  // ---------- 2. 主色 ----------
  const pts = bowtieSample(ok256, 8, 1024);           // 每维 8 档，≤1024 点
  const clusters = kmeans(pts, 5, 5);                 // k=5，5 次迭代
  const seed = clusters.filter(c => c.w >= 0.12 && c.C >= 0.06)
                        .sort((a, b) => b.w * b.C - a.w * a.C)[0] ?? null;
  const { brand, accent, seedHex } = seed
    ? deriveBrand(seed, presetBrand(input.current))
    : { ...presetBrandPair(input.current), seedHex: '#000000' };

  // ---------- 3. busy ----------
  const g = sobel(Y256, 256);
  const edge = countAbove(g, quantile(g, 0.95)) / g.length;
  const hf   = hfEnergy(Y256, 256, 4);
  const skin = skinBlobRatio(img64, 8);
  const busy = 0.50 * clamp((edge - 0.01) / 0.20, 0, 1)
             + 0.30 * clamp(hf / 0.06, 0, 1)
             + 0.20 * skin;
  const isBusy = busy >= 0.62;

  // ---------- 4. 文字安全区 ----------
  const blocks = splitGrid(zone, 4, 4);
  const bed = blocks.map(b => {
    const Cr = contrast(linearLuma(b, Y256), mode === 'dark' ? 0.90 : 0.02);
    let v = clamp(4.5 / Math.max(Cr, 0.5) - 1, 0, 1);
    if (edgeDensity(b, g) > 0.18) v = Math.max(v, 0.62);
    return v;
  });
  const bedMask = bilinearUpsample(bed, 4, 4, 96, 96);
  const bedAlpha = max(bed) * 0.92;

  // ---------- 5. 位置 ----------
  const cand = [{ side: 'left',  x: [0, 0.34] },
                { side: 'middle',x: [0.33, 0.67] },
                { side: 'right', x: [0.66, 1] }];
  const subject = subjectCentroid(g, img16, skin);
  const costs = cand.map(c => ({
    side: c.side,
    cost: 0.45 * macroComplexity(g, img16, c.x)
        + 0.35 * (1 - flatness(Y256, c.x))
        + 0.20 * overlap(subject, c.x),
  })).sort((a, b) => a.cost - b.cost);
  const best = costs[0];
  const suggestedSide = Math.abs(costs[0].cost - (costs.find(c => c.side === 'right')?.cost ?? 9)) < 0.04
    ? input.targetSide : (best.side === 'middle' ? input.targetSide : best.side as 'left' | 'right');
  const conflict = overlap(subject, suggestedSide === 'left' ? [0, 0.34] : [0.66, 1]) > 0.5;

  // ---------- 6. 组装 ----------
  const t = materialOf(input.current, mode);
  return {
    mode, brand, accent, seedHex,
    sidebarOpacity: clamp(t.sidebarOpacity + 0.06 * busy, 0.30, 0.85),
    blur:           clamp(t.blur + 8 * busy, 12, 40),
    bedAlpha:       clamp(t.bedAlpha + (mode === 'dark' ? 0.08 : 0.06) * busy, 0, 0.92),
    bedMask,
    veilDark:  clamp(t.veilDark  + 0.10 * busy, 0.28, 0.60),
    veilLight: clamp(t.veilLight + 0.10 * busy, 0.16, 0.50),
    edgeLuma:   mode === 'dark' ? 0.10 + 0.02 * busy : 0.70 + 0.06 * busy,
    shadowStrength: 1.00 + 0.15 * busy,
    wallpaperBrightness: 1 - 0.08 * busy,
    suggestedSide, conflict,
    contrastReport: measureContrast(ok256, brand, mode, bedAlpha),
    cost: best.cost,
  };

  input.bitmap.close();
}
```

### 5.9 成本与验收

| 阶段 | 预算 | 手段 |
|---|---|---|
| 降采样 + 色彩空间转换 | ≤ 8ms | `OffscreenCanvas`、`max(256, dpr·面板宽)` 上限、`Float32Array` 复用 |
| k-means（5×1024） | ≤ 6ms | 弓形采样降到 1024 点、max 5 次迭代、提前停止 |
| Sobel + 高频 + 皮肤团块 | ≤ 7ms | 积分图算盒式模糊、Sobel 分离卷积、64² 上做连通 |
| 安全区 4×4 + 双线性 | ≤ 4ms | 只在 zone 内采样 |
| 合成与输出 | ≤ 3ms | — |
| **合计** | **≤ 28ms**（目标 40ms 内） | 全部在 Worker；主线程只收结果 |

**自动适配按钮的交互（写成编排，不是「转个圈然后好了」）**：三段式，每段都有可见产出物，总时长 ≈ 520ms + 计算时间：

1. **读壁纸**（0–120ms）：按钮左侧出 12px 环；四个预览格变暗 12%（表示「正在重算」）。
2. **取色**（120–280ms）：主色 swatch 从壁纸缩略图中心**飞入**色板位（`--t-4`），落位后闪一次高光；同时预览四格恢复亮度。
3. **算安全区**（280–440ms）：预览格内叠一层 4×4 网格轮廓，逐块亮起（每块 30ms，**这是唯一允许的 stagger，因为它显示的是计算范围**），亮完后网格淡出，衬底遮罩以 320ms 淡入。
4. **参数归位**（440–520ms）：被自动改动的滑块**自己走到新值**（§3.14 特有态），走过路径留 1.2s 残影；品牌色若变化，用 520ms 插值。
5. **结束**：停在**预览态**（不自动应用），底部出现两行：变化清单（`遮罩 0.34→0.42`、`模糊 30→34px`、`品牌色 #4C9AFF→#8B7BF7`，三行以内，超出的折叠为「还有 N 项」）+ 两个按钮「应用」/「撤销」。**「撤销」把滑块走回原位**，不是瞬跳。

### 6.4 三处「原来 → 改成 → 为什么」（现有代码里真实存在的）

**① `.subbar__meta` 用 `·` 串联 profile 名 / node_modules 状态 / 「N 可更新」**
- **原来**：`App.tsx` 的 `.subbar__meta` 里 `<span className="dim">·</span>` 把三四个字符串串成一行。
- **改成**：拆成**等距列**——列一放 profile（左对齐），列二放 node_modules 状态（固定宽 96px，图标 + 文本），列三放更新计数（右对齐，`--fs-num` + `--p-ember` 角标）。三项用 `display: grid; grid-template-columns: 1fr 96px auto` 对齐；列间距 12px，**不插分隔符**。
- **为什么**：`·` 是模板外壳的特征——它不表达任何关系，只做视觉分隔。等距列则把「这是三个不同维度的字段」直接编码成对齐关系，眼睛可以竖着扫三个值的差异（这正是简报里「第一屏说清状态」的要求）。同时它顺手解决了多 profile 时长度不一导致的跳字问题。

**② `.profiles__meta.mono` 形如 `{depCount} 插件 · {bundleCount} 加载层`（Sidebar.tsx）**
- **原来**：一行等宽文本，两个数字被 `·` 隔开。
- **改成**：这两个数升级为 **§3.9 缝隙刻度** 与 **§3.10 状态卡** 的读数——`deps 42 / bundled 39 / silent 3` 三列等距，缺口的 3 个在读数里是 `--p-ember` 且刻度带上对应格下沉。
- **为什么**：`42 插件 · 39 加载层` 的写法把「42 与 39 的关系」抹平了——读者要自己减。而 **42 vs 39 的差**（3 个已装未加载）才是这个产品最要紧的一眼信息（简报里的「装了什么 vs 加载了什么」）。改成三列读数后，差值是被**画**出来的（刻度带的缺口），不是被算出来的。

**③ `.section-title`（`base.css`）是 `text-transform: uppercase` + `letter-spacing: 0.06em` + 700**
- **原来**：`Profile` / `过滤` 两个标题都用这套样式，且 `Profile` 是英文大写。
- **改成**：`--sb__group` 用中文（「环境」「筛选」）、字重 600、字距 **+0.02em**、**无 uppercase**，只出现 2 次。`base.css` 里的 `.section-title` 保留（其它面板仍在用），但侧栏不再引用它。
- **为什么**：全大写 + 大字距是黑名单第 ⑤ 条第一条，它的作用是「假装权威」而非传达信息。而这个产品**只在两个地方需要分组**（环境三行 / 筛选五项），用中文 + 克制的字距已经足够，字数也短到不需要 uppercase 来撑宽度。附带好处：中文没有大小写，套 uppercase 会让同一属性在不同语言下表现不一致。
